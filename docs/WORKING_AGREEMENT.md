# Working Agreement

A. START OF EVERY STAGE: read WORKING_AGREEMENT.md and CONTRACT.md completely; run `git status` and confirm clean (commit or stash otherwise); run scripts/verify; if anything fails from earlier work, fix it first and note it in the Stage log before new work.
B. Never claim something works unless you ran it in this session. Quote raw command output in docs/evidence/stage-NN.md. If a command cannot run, label the item UNVERIFIED and tell me the exact commands to run. Never invent output.
C. COMMIT GATE: do not tag a stage unless (1) mvn verify is green, (2) jacoco check passes, (3) ArchitectureRulesTest passes, (4) the endpoint walkthrough in the evidence file was actually executed, (5) CONTRACT.md is updated. If any gate fails, commit as "WIP: <reason>" without a tag and list the failures to me.
D. SANITY-BREAK CHECK: for each stage, pick the 3 most critical tests named in the stage prompt, temporarily break the production code they protect, run those tests, confirm they FAIL, then restore with git checkout and confirm they pass. Record the 3 results in the evidence file. This proves the tests are real.
E. Work in small sub-tasks. Commit after each sub-task that passes. My agent quota is limited: if you are running low, stop cleanly, update the Stage log with done / not done / exact next step, commit, and tell me.
F. Do not refactor or restyle earlier stages except to fix a real defect (log it).
G. Secrets: if a real Gemini key is needed for a manual test, ask me in chat; I will enter it in the AI Settings screen or export it in my own terminal. Never write it anywhere. Automated tests always use MockLlmClient.
H. Production standards: DTO records with bean validation on every input; deny-by-default authorization; pagination with max 100; idempotency on payments and bookings; meaningful DB indexes; no PII or health data in logs; OpenAPI annotations on every endpoint; unit tests for logic and integration tests per endpoint (success, validation error, 401, 403, and not-found or conflict where relevant).
I. Health data rules: separate encrypted storage, consent required, redacted in logs and audit args, only coded fields sent to the LLM, 18+ only for nutrition/health features, wording "wellness suggestions, not medical advice".
J. END OF EVERY STAGE: update CONTRACT.md, write docs/evidence/stage-NN.md, run scripts/verify, commit, tag stage-N (only if gate C passes), then reply with: built / verified (with evidence file reference) / UNVERIFIED / known gaps / next stage.
