# FitFlow Stage 5B Evidence Report: Razorpay Payment Gateway, Webhooks, Refunds & Dev Checkout

## 1. Sources of Truth (Razorpay Official Documentation Confirmation)

Before writing any implementation code, the official Razorpay documentation was researched and confirmed for all 5 core payment domain aspects:

### (1) Orders API (`POST /v1/orders` and `GET /v1/orders/{order_id}/payments`)
- **Reference Documentation**:
  - https://razorpay.com/docs/api/orders/create/
  - https://razorpay.com/docs/api/orders/fetch-payments/
- **Create Order Request**:
  - `amount`: Integer in the smallest currency sub-unit (paise for INR, e.g. `49900` for ₹499.00). **Mandatory**.
  - `currency`: ISO code `"INR"`. **Mandatory**.
  - `receipt`: Internal identifier (e.g. `"pay_" + paymentId`), maximum 40 characters. Acts as an idempotency key.
  - `notes`: JSON key-value map (up to 15 key-value pairs, string values <= 256 chars).
  - Basic Authentication header: `Authorization: Basic Base64(key_id:key_secret)`.
- **Create Order Response**:
  - `id`: Unique order identifier starting with `order_` (e.g. `order_RB58MiP5SPFYyM`).
  - `entity`: `"order"`.
  - `amount`: Total amount in paise.
  - `amount_paid`: Amount paid so far (`0` initially).
  - `amount_due`: Remaining amount due in paise.
  - `currency`: `"INR"`.
  - `status`: Order state (`"created"`, `"attempted"`, `"paid"`).
  - `attempts`: Integer count of payment attempts.
  - `receipt`: Internal receipt identifier provided in request.
  - `notes`: Key-value notes echoed back.
  - `created_at`: Unix timestamp.
- **Fetch Order Payments (`GET /v1/orders/{order_id}/payments`)**:
  - Returns collection: `{ "entity": "collection", "count": N, "items": [ { "id": "pay_...", "entity": "payment", "amount": 49900, "status": "captured" | "failed" | "authorized", ... } ] }`.
  - Used by `fetchStatus` and background reconcile jobs to poll terminal payment states.

### (2) Standard Checkout Signature Verification Rule
- **Reference Documentation**:
  - https://razorpay.com/docs/payments/payment-gateway/web-integration/standard/build-integration/
- **Client Callback Parameters**:
  - `razorpay_order_id`: Razorpay Order ID.
  - `razorpay_payment_id`: Razorpay Payment ID.
  - `razorpay_signature`: HMAC-SHA256 hex digest generated by Razorpay.
- **Server Verification Algorithm**:
  - Payload string: `order_id + "|" + payment_id` (joined by pipe character `|`).
  - Secret: Razorpay `Key Secret` (never exposed to client).
  - Signature: `HMAC_SHA256(keySecret, orderId + "|" + paymentId)` formatted as a lowercase hex string.
  - Constant-time comparison: Using `MessageDigest.isEqual(...)` on UTF-8 bytes to prevent timing side-channel attacks.

### (3) Webhook Headers, Verification & Idempotency
- **Reference Documentation**:
  - https://razorpay.com/docs/webhooks/validate-test/
  - https://razorpay.com/docs/webhooks/
- **Headers**:
  - Signature header: `X-Razorpay-Signature`.
  - Event ID header: `X-Razorpay-Event-Id` (unique event instance ID used for deduplication/idempotency).
- **Verification Rule**:
  - Computed on the **RAW, UNPARSED request body bytes** before any JSON parsing or serialization mutations.
  - Algorithm: `hex(HMAC_SHA256(webhookSecret, rawBodyBytes))`.
  - Comparison: Constant-time comparison (`MessageDigest.isEqual`).
- **Idempotency Rule**:
  - Header `X-Razorpay-Event-Id` stored as unique key in `payment_webhook_events`.
  - If a duplicate event arrives, server immediately returns HTTP `200 OK` without reprocessing.
  - If header is absent, fall back to SHA-256 hash of the raw body.

### (4) Refunds API (`POST /v1/payments/{payment_id}/refund` and `GET /v1/refunds/{id}`)
- **Reference Documentation**:
  - https://razorpay.com/docs/api/refunds/create-normal/
- **Request Parameters**:
  - `amount`: Amount in paise to refund.
  - `speed`: `"normal"`.
  - `receipt`: Internal refund reference (e.g. `"ref_" + refundId`).
  - `notes`: JSON key-value map.
- **Response Parameters**:
  - `id`: Refund ID starting with `rfnd_` (e.g. `rfnd_FP8R8EGjGbPkVb`).
  - `entity`: `"refund"`.
  - `amount`: Refunded amount in paise.
  - `currency`: `"INR"`.
  - `payment_id`: Parent payment ID (`pay_...`).
  - `status`: `"pending"`, `"processed"`, or `"failed"`.
  - `receipt`: Internal receipt reference.

### (5) Payment States & Capture Semantics
- **Reference Documentation**:
  - https://razorpay.com/docs/payments/payments/payment-states/
  - https://razorpay.com/docs/api/payments/capture-payment/
- **Payment Lifecycle States**:
  - `created`: Payment initiated on client, awaiting bank authorization.
  - `authorized`: Funds authenticated and held at customer's bank. Not yet settled. (If not captured within 3 days, auto-refunded by Razorpay).
  - `captured`: Payment successfully settled and complete. Safe for order fulfillment.
  - `refunded`: Payment reversed partially or fully.
  - `failed`: Payment attempt failed at bank or cancelled.
- **Capture Requirement**:
  - If auto-capture is enabled on Razorpay account, payments transition directly from `created` to `captured`.
  - If an account has manual capture enabled or payment arrives as `authorized`, FitFlow calls `POST /v1/payments/{id}/capture` with `{ "amount": amountPaise, "currency": "INR" }` to guarantee capture before marking `SUCCEEDED`.

## 4. The 3 Sanity Breaks (Recorded Proof of Rigor)

In accordance with FitFlow verification rules, 3 intentional regressions ("Sanity Breaks") were introduced into the code to prove that the tests actively fail when defensive invariants are removed:

### Sanity Break 1: Forced Signature Check to Always Return True
- **Mechanism**: Set `RazorpaySignatureValidator.sanityBreakAlwaysTrue = true`.
- **Expected Failure**: All negative signature verification vectors (wrong secret, wrong orderId, flipped bit, null parameters) must fail `assertFalse`.
- **Actual Test Output**:
  ```text
  [ERROR] Tests run: 10, Failures: 5, Errors: 0, Skipped: 0
  [ERROR] RazorpaySignatureValidatorTest.testVector3_wrongSecretFails:55 expected: <false> but was: <true>
  [ERROR] RazorpaySignatureValidatorTest.testVector4_wrongOrderIdFails:63 expected: <false> but was: <true>
  [ERROR] RazorpaySignatureValidatorTest.testVector5_flippedBitFails:73 expected: <false> but was: <true>
  [ERROR] RazorpaySignatureValidatorTest.testCheckoutNullAndBlankHandling:81 expected: <false> but was: <true>
  [ERROR] RazorpaySignatureValidatorTest.testWebhookNullAndBlankHandling:92 expected: <false> but was: <true>
  ```
- **Reversion**: Reverted `sanityBreakAlwaysTrue = false`. Tests re-run -> **10 passed, 0 failures**.

### Sanity Break 2: Skip Amount Check on Payment Confirm
- **Mechanism**: Set `RazorpayPaymentGateway.sanityBreakSkipAmountCheck = true`.
- **Expected Failure**: Confirming a payment where Razorpay reports an amount differing from our expected order amount must fail to throw `ApiException(VALIDATION_FAILED)`.
- **Actual Test Output**:
  ```text
  [ERROR] Tests run: 13, Failures: 1, Errors: 0, Skipped: 0
  [ERROR] RazorpayPaymentGatewayIT.testConfirm_amountMismatch:332 Expected com.fitflow.common.error.ApiException to be thrown, but nothing was thrown.
  ```
- **Reversion**: Reverted `sanityBreakSkipAmountCheck = false`. Tests re-run -> **13 passed, 0 failures**.

### Sanity Break 3: Disable Duplicate Event Deduplication on Webhook
- **Mechanism**: Set `RazorpayWebhookService.sanityBreakDisableDuplicateCheck = true`.
- **Expected Failure**: Sending a duplicate webhook payload with the same `X-Razorpay-Event-Id` must not return status `"duplicate"` (instead reprocessing and returning status `"ok"`).
- **Actual Test Output**:

## 5. Architectural Isolation Boundary (ArchUnit Rule 9)

ArchUnit rule `ruleI_razorpayIsolationBoundary` enforces that:
1. No package outside `com.fitflow.payment.gateway.razorpay` may reference Razorpay base URLs or read Razorpay secret names (`razorpay_key_secret`, `razorpay_webhook_secret`).
2. Only `RazorpayPaymentGateway` implements `PaymentGateway` for Razorpay.
3. No foreign packages instantiate `RazorpayClient`.

4. All administrative endpoints (`/api/v1/admin/settings/payments/**`) require `SETTINGS_EDIT` or `SUPER_ADMIN`.
- **Result**: `EndpointSecurityCoverageTest` **PASSED** (100% of routes guarded).
